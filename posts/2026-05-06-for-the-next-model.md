Boris Cherny 是 Claude Code 的作者。在 Sequoia AI Ascent 2026 上他讲了几件事：

- 从 2025 年 10 月起没手写过一行代码
- 单日 PR 记录 150 个
- 同时跑几百个 agent，过夜再跑几千个

这些数字本身没什么值得反复念的。值得单独写一篇的是他讲的另外一件事——Claude Code 头六个月几乎不可用。

## 为不存在的模型造工具

他们做 Claude Code 的时候，Opus 4 还没出。当时的模型跑这套工作流很烂，团队自己也只有 10% 的时间在用它，剩下时间还是手写。他们押注的是"下一个模型"。

5 月 Opus 4 发布，工具突然能用了，采用曲线起来。后面 4.5、4.6、4.7 每出一次就是新一波拐点。

这件事对创业者比 150 PR 那个数字更值钱。大部分人做产品是给"今天的模型"做的——今天 Claude 4.7 能做到什么我就贴着边做。Boris 的反例说：你应该给"6 个月后的模型"做。模型现在 3 到 6 个月一次明显跳跃，产品踩着今天的能力上限，3 个月就过时；产品为还没到的能力做准备，模型一到位采用曲线就上来了。

代价是前 6 个月看上去像废品。这是真正的门槛。能熬过去的是相信曲线的人。

## "coding solved"——对什么样的代码

他原话有限定语：他写的是 TypeScript / React 项目，从零起的新代码。大型遗留代码库、冷门语言"等下一个模型就行"。

我自己用 Claude Code 的体感和这个一致。给自己写的小工具——拉飞书数据、跑分析、出图——基本不再手写。我的代码是副产品，是给我一个人用的。这一类"代码"模型做得比我亲自写更快、更稳。

但放到生产级长期维护的代码上，还差一层。Boris 在 Anthropic 内部跑的是 Anthropic 自己的代码库，那是全球最强工程师维护的、模型最熟悉的栈。普通公司的祖传 PHP、老 Java，模型现在不行。

所以"coding 已解决"这句话不是普世结论，是一个具体场景下的判断。但这个场景在迅速扩大。

## AI-native 公司的 10x 窗口

他讲的第三件事，对我做 JuziBot 最有用。

老公司的优势是流程、客户关系、规模。AI 让这些都打折：

- **流程**：模型能学会工作流，新公司不用重新摸索，直接抄
- **切换成本**：模型能把客户的旧系统迁到新系统
- **组织摩擦**：让 5000 人的公司转 AI-native，比从零起一家 AI-native 难一个数量级

意思是，你做的不是"在 AI 时代加点 AI 功能的 SaaS"，你做的是"AI-native 从第一天起就是这样长出来的公司"。这两个看起来在做同一件事，出来的东西完全不同。

卖给客户的不是"AI 帮你做客服"，是"客服这件事被重新定义"。前者是给老需求换工具，后者是给新需求造工具。前者市场大但天花板低，后者天花板还没人摸到。

## 印刷术那个类比

他用印刷术做类比：写字曾经是少数人的技能，识字普及用了几百年。代码到普及他赌不会这么久——基础设施已经在那里。

这个比喻有用，但不要被它带跑。印刷术之后，"识字"变成普通能力，"会写好东西"依然稀缺。代码也一样：模型把"能写代码"降到接近零成本，稀缺的东西从手指头会动转移到——你知道要做什么、你能判断模型做对没有、你能设计还没人见过的产品。

这三件能力，技术背景不是必要条件。产品判断力、领域知识、对现实约束的体感，是。

## 我的一个 takeaway

我现在做战略分析、拉数据、写 deck，越来越多放手让 Claude Code 跑。我不再写脚本，我写 prompt。这件事的临界点不是"模型够强"，是"工具够顺手"。Claude Code 自己就是 product overhang——它今天的形态，是为下一个 Opus 准备的。

我做 JuziBot 的产品判断也得是这个逻辑。今天客户用得勉强的功能，要为模型再跳一档之后做。听上去像赌，但不下注就是另一种赌。
