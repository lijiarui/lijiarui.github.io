> 大部分时间我在手机上工作。打开 Claude app，左侧有一个 code tab，里面通常有 5 到 10 个 session 在同时跑，每个 session 里有多个 agent，加起来大概几百个。每天晚上还有几千个 agent 在做更深入的工作。
>
> <span class="cite">——Boris Cherny，Claude Code 作者</span>

这就是我想去的方向。

不是因为几百个 agent 听起来酷。是因为这是我目前看到、把"想清楚"和"做出来"之间距离压到最短的工作方式。

前几天写了 [《接近 10 年没写代码了，被 Claude Opus 4.5 拉了回来》](/thought/2026-04-28-return-to-code/)，立了一个"Claude 永动机"的 flag。一周下来，永动机已经在跑。这是第一篇实操贴。

## 我现在的永动机长什么样

每天的工作方式：

- 早上开 6-8 个 Claude Code 窗口，每个跑一条线
- 想到一件事 → 起一个新 session 丢给它 → 切回去看上一个 review 完没
- 永远是它等我，不是我等它

具体在跑的活，比如：

- 客户留存数据：拉飞书 Bitable → 分组 → 出图 → 我看一眼出结论
- 北大那场分享后的 follow-up deck：跑 outline → 我改方向 → 它再细化每页
- AI 原生组织实验：把销售 SOP 拆成 skill → 让 Agent 跑一遍 → 看漏在哪
- 博客（包括这一篇）：我说想法 → 它出草稿 → 我改 → 它再改

跑到现在最直接的体感：每天能落地的事比上周多了 3 倍。瓶颈整个换了——以前卡在"我没时间做"，现在卡在"我审得有多快"。

## 离 Boris 还差什么

差距很具体。

**手机上跑不起来。** 我还黏在 Mac 上。Boris 在手机跑意味着每段碎片时间都接进了永动机——地铁、等饭、走路。我现在离开电脑就停了。这一段带宽损失最直接。

**Session 一多就管不住。** 现在 6-8 个我已经在切的过程中漏事——哪个跑完了、哪个卡住了、哪个产出我看过、哪个还没看，全靠脑子记。再往上加到几十个，必崩。Claude app 里大概有现成的，我还没花时间研究；不行就自己写一个看板。

**过夜的几千个 agent 还没起来。** 白天的活我能盯。"过夜跑更深的活"是另一个量级——意味着 agent 跑的是我还没完全想清楚的探索性任务，第二天 5 分钟扫完决定要不要跟。这件事的卡点是信任。要建立信任，得先有一套 agent 不互相迎合的 review 机制（return-to-code 里讲过这个问题）。

**审的速度追不上写的速度。** 现在已经能感觉到，我看 Claude 产出的速度比它产出的速度慢。再放大 10 倍，没有筛选机制就是噪音淹没信号。需要一个中间层——让一个 meta agent 先看完所有产出，标好"值得 Grace 看 / 自己改了重跑 / 跑歪了停掉"。

## 下一步要解的题

按重要性排，接下来一周要做的事：

1. **手机端工作流跑通。** 出差一次只带手机不带电脑，强迫自己适应 Claude app 的 code tab
2. **Session 看板写出来。** 一个最 hack 的版本就行——甚至可以是个飞书 Bitable，每个 session 一行：跑什么、状态、产出位置、是否已 review
3. **过夜任务从一个具体场景试起。** 比如让几个 agent 通宵做某客户的竞品调研，第二天看质量。跑通一个再扩到第二个
4. **二级筛选的 meta agent。** 这个最难，留到后面。前三件做出来再说
